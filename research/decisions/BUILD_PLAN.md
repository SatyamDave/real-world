- Date: 2026-10-11
- Status: proposed
- Rests on: [0001-architecture](0001-architecture.md), [0002-benchmark-and-receipts](0002-benchmark-and-receipts.md), the specs in [`product/`](../../product/README.md), [SYNTHESIS.md](../SYNTHESIS.md), [lenses/cto.md](../lenses/cto.md), [lenses/cpo.md](../lenses/cpo.md), [lenses/red-team.md](../lenses/red-team.md)

## What "done" means

On a laptop with no API keys, `make setup && make dev` gives a working product on fixture data:

1. A 10,000-agent world for 16 countries is sampled from bundled marginals, each country graded A-D.
2. `make daily-fixtures` runs the daily cycle over five fixture days: news becomes signals, beliefs move and are nudged toward polls, three forecasters forecast every open question, the day's forecasts are hashed into a chained Merkle root, resolved questions are scored, and the spread audit marks experimental countries. Rerunning it costs nothing.
3. `POST /v1/simulate` forks today's world with an event over N days and K members and returns a typed result with an ensemble band, segment shifts, coverage tiers, cost, a content hash and a trace; it refuses up front when over its cost cap.
4. The Python and TypeScript SDKs run their README quickstarts against the local API.
5. The web app shows the daily question with an instant reveal, receipts with in-browser verification, a fork running into a shareable card, and a globe where clicking a country opens one agent with "What moved this agent" and "In its own words".

With `ANTHROPIC_API_KEY` set, the same commands call Claude Haiku 5.5 (`claude-haiku-5-5`) and every call lands in `llm_calls` with its cost.

## Rules for every slice

- One slice is one Zeroshot run and one PR, touching only the files it lists. Slices in the same parallel group have disjoint files, so they run at the same time in separate worktrees cut from `main` after their dependencies merge.
- Run each with the `opus-change` graph (worker, acceptance verifier, code verifier, repair loop). Write the brief to `task.json` as `{"task": "<brief>"}`, run `zeroshot run --title "<id> <title>" --profile local:opus-change --input task.json --validate-only`, then without `--validate-only`. Delivery (push, PR) is chosen by profile, never by flag. A run counts as done when both verifiers accept and `make check` is green, not when a PR exists.
- The PR uses the repo template, a conventional title (`feat(engine): ...`) and links the slice's research in Why, so `pr-quality.yml` passes. Over 400 changed lines outside docs and data, the PR says why it could not be split.
- No dependency beyond those the brief names. No change to a published forecast or the receipt format without a new decision.
- A PM reviews each PR against "What a PM sees" below; an engineer reviews the diff.

## Order and parallelism

```
group 0   S01 scaffold
            │
group 1   S02 population   S03 beliefs   S04 news   S05 ledger   S06 scoring     (5 in parallel)
            │                 │             │          │             │
group 2   S07 forecast (S02,S04,S05)        S09 simulate (S02,S03,S04)            (2 in parallel)
            │                                   │
group 3   S08 daily cycle (S02-S07)             │
            │                                   │
group 4   S10 API (S08, S09) ───────────────────┘
            │
group 5   S11 SDKs
            │
group 6   S12 web app
```

Critical path: S01 → S04 → S07 → S08 → S10 → S11 → S12, seven runs. At roughly one run per half day including review, the base is working by about Oct 15-16, which leaves the API freeze (Oct 16-20) and launch work on top of a running system.

## After the base (not in this plan, each its own slice)

1. **Receipts go live** (before the first public hash, target Oct 14, so it may jump the queue right after S05): OpenTimestamps and one FreeTSA RFC 3161 token per day record, a public `real-world-receipts` git mirror, the receipts page showing pending vs anchored. Format unchanged ([0002](0002-benchmark-and-receipts.md)).
2. **Hosting** (decision 0003): pick GitHub Actions cron plus one Fly machine or Modal; Postgres and R2 for `var/`; dead-man alert at 08:00 UTC; Batch API for the nightly forecast step.
3. **Real data**: GDELT GKG loader and Kalshi/Polymarket price snapshots in the fixture shapes; GLOPOP-S loader once its licence row clears.
4. **Cost measurement**: 1,000 real Haiku 5.5 calls through `llm_calls` to replace every estimate in the research.
5. **Guardrails**: the acceptable-use policy check on fork events and election-window mode, by Oct 20.
6. **Accounts and keys**: planned as slices P1-P7 in [0011](0011-consumer-product-and-api.md#build-plan).
